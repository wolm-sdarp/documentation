# Инструкция по работе с проектом WLM_SDARP_PROJ для LLM

## 0. О файле

- Документ предназначен для LLM(s), которая/которые используются при работе над проектом.
- Файл описывает, как LLM взаимодействует с материалами проекта, каких принципов работы, правил и ограничений придерживается.
- Этот файл хранит базовые инструкции. Дополнительные инструкции от конкретного пользователя лежат в [[LLM_INSTRUCTIONS_PERSONAL]].
- Файл ссылается на другие источники информации о проекте — если они необходимы для выполнения задачи, их нужно изучить.

## 1. О проекте

### 1.1. Паспорт проекта
#### Название проекта
**WoLM SDARP**
#### Цель проекта
Cоздать серию качественных книг и дополнительных материалов для самостоятельного глубокого и системного освоения анализа данных с нуля психологами широкого круга специализаций с опорой на современные методические подходы.
#### Тип проекта
Образовательный продукт с IT-основой.
- образовательная сторона — книги, тесты, задания, проектные работы.
- IT-основа — Git, GitHub, Quarto, публикация материалов в формате сайта.
#### Аудитория результатов
  - студенты-бакалавры и магистранты психологических специальностей — как дополнительная литература к университетским учебникам
  - аспиранты и молодые исследователи — как самоучитель «с нуля до pro»
  - практикующие исследователи из академии и индустрии — как справочник по сложным вопросам и неоднозначным решениям
  - преподаватели университетов — в качестве методических материалов и учебных пособий
  - все интересующие статистикой и анализом данных в психологии и социальных науках
#### Этап, задачи и сроки
Смотри GH Project [**WoLM SDARP PM**](https://github.com/orgs/wolm-sdarp/projects/1) в GH Organization.
- Подробнее об организации, репозитория и проектах см. 
#### Критерии успеха
- Задачи высоких приоритетов выполнены вовремя.
- Задачи средних приоритетов выполнены.
- Задачи низких приоритетов выполнены или перенесены в следующий milestone.

## 2. Организация файлов
### 2.1. Структура директории проекта

- Таблица репозиториев: [[git-gh-docs#GitHub Repositories]]
- Локальная структура: [[git-gh-docs#Локальная структура]]
- Документация для внутреннего пользования (в том числе для LLM) лежит в `documentation/tech/`
### 2.2. Правила именования
- Только латиница, цифры, `_` и `-`; без пробелов и спецсимволов
- Версия повышается при существенной переработке; мелкие правки версию не меняют
- Не называть файлы «финал», «финал2», «новый» — для этого есть версии и `CHANGELOG.md`
### 2.3. Форматы результатов
| Тип материала                  | Формат                                      |
| ------------------------------ | ------------------------------------------- |
| Результаты работы по умолчанию | `.md` (один файл на одну задачу)            |
| Таблицы и расчёты              | `.xlsx` / `.csv` — только по прямой просьбе |
| Документы для отправки         | `.docx` / `.pdf` — только по прямой просьбе |
| Презентации                    | `.pptx` — только по прямой просьбе          |
| Код                            | обычные файлы кода в `claude`               |

## 3. Правила работы LLM
### 3.0 Политика использования ИИ в проекте
- См. документ [[ai-usage-policy]].
### 3.1 Языки
#### Язык общения
- отвечай на том же языке, на котором пользователь прислал запрос
	- исключения:
		- в запросе пользователя указан язык ответа
		- в [[LLM_INSTRUCTIONS_PERSONAL]] пользователем задан язык общения или ответов
#### Язык результатов
- код
	- по умолчанию: R
	- детали: см. [[#Языки, фреймворки, версии, менеджер пакетов]]
- текст: см. [[#Язык материалов]]
#### Язык материалов
- зависит от того, над какой частью проекта ведется работа
	- уточнить у пользователя, если не объявлено ранее
- о работе с дореформенной орфографией и локализацией — см. [[pre-reform-ru-orthography]]
- о стилистике текста в материалах в дореформенной орфографии — см. [[pre-reform-ru-style]]
### 3.2 Планирование и согласование
### 3.3 Уточняющие вопросы
- Оценить достаточность предоставленной информации
- Рассказать о том, какой информации не хватает
- Спросить пользователя: *сделать разумные допущения* или *запросить уточнения*
	- Если ответ «сделать допущения», приступить к выполнению задачи
	- Если ответ «запросить уточнения», то задать уточняющие вопросы
### 3.4 Большие и многоэтапные задачи
- Разбить задачу на этапы:
	- план → черновик → ревью → финал
- После каждого этапа — контрольная точка, чтобы не потерять время на неверное направление
### 3.5 Формат ответа
- Короткое резюме результата в чате + ссылка на файл
- Список допущений и вопросов, оставшихся открытыми
- Что изменилось (если правились существующие файлы)
- Предлагать следующий шаг, но не выполняю его без запроса
### 4. Безопасность и использование ИИ
- Работа с ИИ регулируется документом [[ai-usage-policy]] — LLM обязана следовать ему
- LLM запрещено писать в зелёные папки
	- Цвет папки — см. теги в [[git-gh-docs#Локальная структура]]
### 5. GitHub и Git
- Работа ведется в GitHub Organization: https://github.com/wolm-sdarp

### 6. Постановка задач
- Раскладывать промпт с задачей по данному шаблону 
```
Задача: [что нужно сделать]
Материалы: [какие файлы / папки использовать]
Результат: [формат, объём, куда положить — по умолчанию один md-файл]
Ограничения: [сроки, стиль, что нельзя трогать]
Критерий готовности: [как проверим]
```
- Если промпт разложить невозможно, попросить пользователя прописать задачу по пунктам.
### 7. Преемственность
#### Фиксация изменений
- Изменения фиксируются в истории Git-коммитов
- Изменения описываются в файлах `CHANGELOG.md`
#### Передача контекста
- Контекст и инструкции передаются между чатами через механизмы LLM — instructions, context и другие.
	- Проверить, есть ли в instructions путь к этому файлу: `documentation/tech/LLM_INSTRUCTIONS_RU.md`
		- Если нет, попросить пользователя добавить.
#### Личное и секретное
- Личные предпочтения пользователя описаны в [[LLM_INSTRUCTIONS_PERSONAL]].
	- Если файл отсутствует, игнорировать.
- Секретные данные (пароли, личные токены доступа пользователя и др.), личную информацию, идентификационные данные и другую чувствительную информацию в память не сохранять.
